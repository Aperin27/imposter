# Stage 1 implementation contract

- React/TypeScript client and a single Worker with bundled static assets; one named SQLite-backed Durable Object per six-character room code.
- Persist the complete room record and next alarm together before broadcasting transitions. Hibernating sockets retain only player IDs and connection validity in attachments. No continuous backend timers.
- The server alone selects participants, questions, imposter and deadlines. Each client receives an explicit filtered view: their question and submitted answer while answering, everyone's answers in discussion, and identity plus both questions only after a public reveal.
- A round snapshots connected participants. New players can join in the lobby or after reveal; existing players can reconnect at any time. Disconnected participants retain their slot and answer. Missing answers become “No answer” after 90 seconds; a round always ends after 20 minutes.
- Intentional host departure immediately promotes the earliest-joined remaining player; an offline successor receives the same 90-second reconnection grace. Unexpected loss preserves the host for 90 seconds, then promotes the earliest connected player. With nobody connected, the first returning player becomes host after the grace period. A prior host never reclaims authority automatically.
- Secure 256-bit session credentials are stored per tab in sessionStorage, preserving refresh and allowing independent local tabs. One current socket per credential; replacing a socket invalidates its predecessor. Credentials are sent via WebSocket subprotocol, never query strings. Do not log request bodies or protocol headers.
- Rooms expire after 30 minutes without a connected player, or a maximum lifetime of 24 hours. Offline player slots remain reserved until intentional departure or room expiration. Codes may be reused only after expiration.
- Acceptance: permission/privacy tests; all-submitted and deadline transitions; early/duplicate reveal; host grace/ordering/reconnect; durable persistence and real WebSocket integration; typecheck and production build. Local checks do not establish deployed behavior or unlimited free capacity.
- No existing data or migrations to preserve. Migration v1 uses `new_sqlite_classes`. Rollback is local file removal before deployment; future persisted-schema changes need explicit migrations.
